# Create Your First Agent

Once Agent Manager is installed, you can create your first agent from the console.

## Choose an Agent Type

1. Navigate to **Agents** in the left sidebar.
2. Click **Add Agent**.
3. Choose how you want to get started:

- **Externally-Hosted Agent** — Connect an agent already running outside the platform. WSO2 Agent Manager provides observability and governance without managing the deployment.
- **Platform-Hosted Agent** — Deploy and manage the full agent lifecycle directly on WSO2 Agent Manager, including build, deployment, scaling, and observability.

## Register an Externally-Hosted Agent

Use this path when your agent already runs somewhere outside WSO2 Agent Manager — locally, on your own infrastructure, or in a third-party cloud. Agent Manager doesn't build, deploy, or manage the process for an externally-hosted agent; it only provides observability (traces, metrics, logs) and governance (AgentID, RBAC, evaluation) once the agent starts reporting in.

Fill in the **Agent Details** form:

| Field | Description |
|-------|-------------|
| **Name** | A display name for your agent (e.g., `Customer Support`) |
| **Description** *(optional)* | A short description of what this agent does |

Click **Register** to complete the registration. You're taken to the agent's **Overview** page, where a **Setup Agent** panel opens automatically with a zero-code instrumentation guide for your agent's language.

### What Happens After Registration

- **AgentID provisioning starts immediately.** Unlike a Platform-Hosted agent, an externally-hosted agent has no deploy or promote step — AgentID credential provisioning begins for every environment in your organization as soon as you click **Register**. See [Retrieve AgentID Credentials for an Externally-Hosted Agent](../tutorials/retrieve-agentid-for-externally-hosted-agents.mdx) when you're ready to wire that credential into your agent.
- **No traces until you instrument it.** The agent won't show any observability data until you connect it. Generate an **Agent API Key** from the Setup Agent panel (or later from the agent's Overview page) and set it, along with the OTel endpoint, as environment variables for your agent process.

For the full picture of how instrumentation works for externally-hosted agents — the zero-code path (Python via the Traceloop SDK, or Ballerina), the manual `init_otel()` path for other languages and frameworks, the environment variable contract, and version compatibility — see [AMP Instrumentation](../guides/amp-instrumentation.mdx).

## Create a Platform-Hosted Agent

### Step 1: Choose a Source Type

Select how the agent source will be provided:

- **Source Code** — Point to a GitHub repository containing your agent code. The platform builds and deploys it automatically.
- **Agent Catalog** — Pick a pre-built agent kind from the Agent Catalog.

### Step 2: Fill in Agent Details

Provide a **Name** (e.g., `Customer Support Agent`) and an optional **Description**.

### Step 3: Repository Details *(Source Code only)*

| Field | Description |
|-------|-------------|
| **GitHub Repository** | Full URL of your repository (e.g., `https://github.com/username/repo`) |
| **Branch** | Branch to build from (default: `main`) |
| **Project Path** | Path within the repository where the agent code lives (default: `/`) |

:::tip Don't have an agent to deploy yet?
Use one of the ready-made [sample agents](https://github.com/wso2/agent-manager/tree/main/samples) instead of bringing your own repository. Set **GitHub Repository** to `https://github.com/wso2/agent-manager`, **Branch** to `main`, and **Project Path** to one of the sample folders below:

| Sample | Project Path | Description |
|--------|---------------|-------------|
| Customer Support Agent | `samples/customer-support-agent` | LangGraph + FastAPI travel assistant that searches for and books flights, hotels, and car rentals |
| Hotel Booking Agent | `samples/hotel-booking-agent` | LangGraph + FastAPI assistant for hotel search, availability checks, and booking management |
| IT Helpdesk Agent | `samples/it-helpdesk-agent` | LangGraph + FastAPI L1 IT support assistant for password resets, access requests, and ticketing |
| CrewAI Agent | `samples/crewai-agent` | Two-agent CrewAI + FastAPI sample that shows how a multi-agent app appears as a single trace |
| Content Writer Platform | `samples/content-writer-platform` | Multi-agent content pipeline with separate writer, reviewer, and frontend services |
| Manual Instrumentation Agent | `samples/manual-instrumentation-agent` | Minimal agent that emits OpenTelemetry GenAI spans by hand, without the Traceloop SDK |
| .NET Agent | `samples/dotnet-agent` | .NET port of the manual instrumentation sample, registered as an externally-hosted agent |

Each sample's requirements — required API keys, environment variables, and any setup steps specific to that agent — are documented in its own `README.md` in the sample's directory. Check it before deploying so you know what to fill in at [Step 7: Set Environment Variables](#step-7-set-environment-variables-optional).
:::

#### Using a Private Repository

If your repository is private, you need to provide a **Git Secret** that contains a GitHub Personal Access Token (PAT).

1. In the **Git Secret** dropdown, select an existing secret or click **+ Create New** to add one.
2. When creating a new secret, provide a **Name** and paste your GitHub PAT. The token must have `repo` scope to allow the platform to clone your private repository.
3. The secret is stored securely and reused across agents that need access to the same repository or organization.

### Step 4: Build Details *(Source Code only)*

Choose a build type:

- **Python** — Provide a **Start Command** (default: `python main.py`) and select the **Language Version** (e.g., `3.11`). Dependencies are auto-installed from `requirements.txt`, `pyproject.toml`, or `package.json`.
- **Docker** — Use a `Dockerfile` in the repository.

**Enable auto instrumentation** *(Python only, checked by default)*

Automatically injects OpenTelemetry tracing into your agent for observability with zero code changes. You can also pin the **AMP Instrumentation Version** used by the init container.

### Step 5: Select an Agent Type

Choose how your agent receives requests:

| Agent Type | Description |
|------------|-------------|
| **Chat Agent** | Standard chat interface. Exposes `POST /chat` on port `8000`. Request: `{message: string, session_id: string, context: JSON}` — Response: `{response: string}` |
| **Custom API Agent** | Custom HTTP API. Specify your own OpenAPI specification and port configuration. |

### Step 6: Configure LLM Providers *(Optional)*

Click **+ Add** to bind one or more LLM providers to this agent. LLM providers are configured separately — see [Register an LLM Service Provider](../guides/register-llm-service-provider.mdx).

### Step 7: Set Environment Variables *(Optional)*

Add any environment variables your agent requires at runtime. Mark sensitive values as **Secret** to store them securely.

:::note Required for most agents
This step is optional at the platform level, but most agents — including every sample above — won't start without their required environment variables (API keys, database URLs, etc.) set here.
:::

### Step 8: Mount Files *(Optional)*

Mount configuration files or other static files into your agent's container at runtime.

1. Click **+ Add File Mount**.
2. Fill in the following fields for each file:

| Field | Description |
|-------|-------------|
| **File Name** | A unique name to identify the file (max 253 characters) |
| **Mount Path** | Absolute path where the file will be available inside the container (e.g., `/workspace/config/settings.yaml`) |
| **Content** | The file content (max 1 MB) |
| **Sensitive** | Toggle on to store the content as a secret |

Duplicate file names are not allowed.

Click **Deploy** to build and deploy the agent.
